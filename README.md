# УЧЕТ ФИНАНСОВ

### Проект модуля для управления личными финансами

## Описание

Программа моделирует упрощённое приложение для ведения личных финансов. Она позволяет пользователю управлять банковскими счетами, категориями доходов и расходов, а также операциями по счетам.

## Структура

### Доменные классы

Доменные классы являются имплементациями интерфейса **FinanceElement**:

- **BankAccount** - описывает банковский счет: содержит уникальный идентификатор, название, текущий баланс. Предоставляет функционал: переименования, пополнения, снятия.

- **Category** - содержит уникальный идентификатор, группирует операции по типу (доход или расход) и имеет описание.

- **Operation** - описывает движение средств: уникальный идентификатор, тип (доход/расход), сумма, дата, описание, привязка к счёту и к категории.

Для упрощения и валидации формирования операции добавлен класс **OperationBuilder**. Поэтому конструктор **Operation** объявлен *protected*, чтобы клиентский код вне модуля мог создавать операции только через *Builder*.

### Сервисы

Общей составляющей для обмена информацией между сервисами является хранилище активных для учета доменных сущностей, представленное классом **Repository**. Он хранит в себе рассматриваемые счета, категории, операции, предоставляет функционал по добавлению, удалению, проверки наличия сущностей, а также фиксирует последние изменения внутри себя (новый элемент или последний удаленный элемент).

Методы, изменяющие состояние **Repository** (добавление, удаление) объявлены *protected*, чтобы сделать их доступными из доверенного класса **RepositoryManipulator**. Его задача поддерживать логичную целостность хранимых сущностей, например:
- при удалении счета удалять связанные с ним операции;
- при удалении / отсутсвии категории перекатегоризировать операции в категории прочих расходов / доходов;
- при добавлении категории обратно - возвращать операциям исходные категории;
- для добавления операции проверять, что активен ее счет;

Взаимодействие сервисов реализовано через управляющий класс **Manager**, который предоставляет интерфейс для взаимодействия с клиентом и реализует в себе роль *Subject* паттерна *Observer*, а сервисы являются его наблюдателями. Соответственно **Manager** применяет **RepositoryManipulator**, фиксирует новый **Action** и оповещает сервисы, что произошли изменения, и каждый сервис реагирует так, как ему нужно для своих задач.

Для сервисов введена соответсвующая иерархия сущностей интерфейса **AutoUpdateTask**, с помощью которых клиент может конфигурировать, какой функционал сервисов он желает поддерживать автоматически обновляемым при изменениях.

Сами сервисы являются наследниками класса-наблюдателя **Service**, расширящие его конкретным функционалом.

В проекте реализованы 2 базовых сервиса:

1. Сервис аналитики **AnalyticService**, его функционал:

    - давать информацию о суммарных доходах / расходах / прибыли по операциям за определенный расчетный период;
    - группировать операции по категориям за определенный расчетный период;
    - давать информацию о доходах / расходах по операциям по категориям за определенный расчетный период;

2. Сервис управления счетами **BankAccountService**, его функционал:

    - обновлять балансы счетов по информации операций;
    - давать информацию о общем балансе клиента;
